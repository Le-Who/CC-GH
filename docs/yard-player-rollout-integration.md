# Yard player integration candidate, 2026-10-04

## Status and baseline

This is a closed rollout implementation, not release acceptance or a deployment.
The source baseline is PR47's exact tree `b188563cc86dbb3f0bf61ddddffe7cacf8f619a2` (published head supplied by parent: `b328dc15d77e981db3646bd16751d7c7594d1c19`). The local baseline commit is only a local wrapper around that tree. No production data, remote branch or acceptance flag was changed.

`YARD_PLAYER_RELEASE_POLICY.enabled` is false. Ordinary, unmigrated accounts retain legacy simulation, mutation protocol and presentation. Source gates for Mochi, Pebble, Pip and the family remain false. A save with **any** `_yardV2` marker, including null or a future format, never re-enters the legacy normalizer; with the rollout closed it is preserved and displayed in a non-gameplay read-only shell before any raw Yard arrays reach presentation.

The reviewed overlay work is integrated behind this code-owned boundary:

- `routes/player.js`: existing authenticated GET `/api/player/snapshot` catches up through the selected adapter; POST `/api/player/mutate` dispatches persistent `yard-v2:` commands only when enabled; sanitized `yardRuntime` is included for migrated accounts. All 14 actions share durable receipt handling. Request bodies cannot set acceptance, profile registries or server time. Old `/api/pet/room/place` and `/pickup` stay retired (410).
- `playerManager.js`: selected initialization inside the existing fresh-read/CAS owner; realtime carries the matching runtime. No SQL table or player-schema bump. Persistent format remains `yard-persistent/v1`, version 1, player schema 11.
- `routes/mergeRoutes.js` and `game-logic/merge-lab-service.js`: refuse new Yard grants to paused/malformed persistent targets before debit. Existing Merge receipts remain replayable; `yardV3ProjectsEnabled` remains false.
- `src/game-state/useGameHub.js`: immutable v2 outbox payloads, same-transaction runtime replacement and Yard inventory aliases, preserving current account/session and Garden boundaries.
- `src/app/gameChunks.jsx` plus `YardReleaseGame.jsx`: lazy legacy or persistent view. A paused persistent snapshot selects a non-gameplay read-only shell before raw arrays reach a renderer. `registry.js` and `defaultLayouts/room.json` register the reserved status strip and background tuning.
- `released-prop-profiles.mjs`: source-bounded Moon/Fountain geometry and condition IDs are prepared, but not registered until family acceptance and every family profile agree. They then join UI shop/place/move and placement geometry instead of relying only on acceptance-harness props.
- `CourtyardGame.jsx`: Back uses the current Home navigation path. Missing actor-specific suggested coordinates start a movable placement cursor at the center, subject to existing validation; this is not a migration placement or guaranteed valid spot.
- `scripts/game-loading-graph.mjs` and `perf-build-guard.mjs`: recognize/count both the real room wrapper entry and the Courtyard entry. No build or decoded-memory budget was increased.

## Migration and rollback warning

The migration is additive and idempotent under the existing PostgreSQL CAS, with one scoped immutable original-input archive. It does not require a SQL migration. Nevertheless, once persistent writes occur, rolling the app image back to pre-integration `84d252d4` is unsafe: that image still normalizes/truncates Yard history and ignores persistent receipts. A rollback-safe image must contain this boundary and set rollout false, leaving structurally valid migrated Yard read-only while unrelated games retain their current release behavior. Do not restore the original Yard backup as routine rollback because subsequent purchases/gifts would be lost. Review this operational change before the first real account migration; no production migration has been performed here.

## Known inherited corruption limitation

Malformed Yard list/album shapes and future markers now select a safe non-gameplay read-only shell whenever the server can produce a snapshot. Invalid Yard economic evidence (for example a string treats balance or string inventory map) still fails existing cross-domain Merge snapshot validation with INVALID_INTEGER/INVALID_DATA. Those corrupt accounts remain snapshot-blocked and require review; this candidate does not claim every malformed account remains browsable. Do not bypass Merge migration for every paused Yard: that would reopen legacy Merge for valid saves. A separate scoped corrupt-account recovery design is needed if complete availability under economic corruption is a release requirement. Raw evidence is not normalized or rewritten.
